## Step 0 — Boot the preview server

```bash
cd <repo-root>
pnpm build                              # rebuild dist/ (~60s; postbuild copies legacy + runs Pagefind)
python3 -m http.server 4321 --directory dist --bind 127.0.0.1
# OR (if wrangler installed and you want to test _redirects too)
# pnpm exec wrangler pages dev dist/ --port 4321 --ip 127.0.0.1
```

Open <http://127.0.0.1:4321/> in Chrome.

**Caveat — the Cloudflare adapter ships `dist/_worker.js`, which intercepts
all requests when wrangler is the server.** This means `_redirects` rules are
NOT exercised against the worker locally; the actual 301 behavior only
surfaces on a Cloudflare Pages preview deploy. Use python's static server for
canonical 200 testing; defer 301 testing to the deploy preview (Phase 6).

## Step 3 — Six-pillar visual checklist (per route × per viewport = 5 × 3 = 15 cells)

For each route + viewport pair, eyeball these 6 pillars:

1. **Hierarchy.** Hero → body → related/footer reads top-to-bottom. h1 dominant; section headings clear; no orphan blocks.
2. **Spacing.** 16 px gutter, 24 px section gaps, 64 px hero padding-top. No collapsed margins, no doubled gaps.
3. **Mobile-first (360 px especially).** No horizontal scroll — confirm via DevTools: `document.documentElement.scrollWidth === window.innerWidth`. Hamburger renders, drawer opens.
4. **Contrast.** Body text on `var(--bg)` (#0a0a0c) is legible — should be WCAG AA (≥ 4.5:1) on every page.
5. **Touch targets.** All buttons, dropdown items, and section toggles ≥ 44 × 44 px at 360 px width.
6. **Pattern parity.** Hero, card, footer all match the existing archive pages (`/aaro/`, `/nasa/`). No surprise typography, no off-brand spacing, no different button styles.
