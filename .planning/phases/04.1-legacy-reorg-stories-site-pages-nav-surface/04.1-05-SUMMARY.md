## Accomplishments

- **Nav.astro extended with two dropdown groups** added as `<li class="nav-dropdown">` siblings after the 4 archive links. STORIES panel lists 8 featured stories in invariant `{1..8}` order (Tic-Tac, Gimbal, Roswell, Rendlesham, Trans-en-Provence, Varginha, Falcon Lake, Phoenix Lights) + divider + `All stories →`. ABOUT panel lists 6 site pages (About, FOIA, Glossary, Map, Timeline, What's New).
- **Pure-CSS desktop dropdowns** via `:hover` + `:focus-within` with `position: absolute; right: 0` so panels never overflow the viewport.
- **Mobile collapsible sections** via inline `<script is:inline>` that intercepts trigger clicks only when `matchMedia('(max-width: 719.98px)').matches`. Esc closes panel + refocuses trigger. Existing anchor-click handler also closes any open dropdown to prevent stale `.open` state on bfcache restore.
- **W-3 build-time gate** in Nav.astro frontmatter: throws clear error if `stories.json` featured entries ≠ 8 OR duplicate orders OR not exactly `{1..8}`. Surface drift fails build, not the nav.
- **Footer.astro extended with Pages + Stories columns** inserted between License and Archives so the visual hierarchy reads About → Source → License → Pages → Stories → Archives. Existing 4 columns unchanged.
- **W-1 footer-grid fix:** `repeat(4, 1fr)` replaced with `repeat(auto-fit, minmax(160px, 1fr))`; 3-column breakpoint at ≤960 px; CLAUDE.md §8 mobile baseline (≤719.98 px) collapses to single column.
- **All touch targets ≥ 44 px** (CLAUDE.md §8). Dropdown items: `min-height: 44px` + `padding: 10px 16px` desktop / `padding: 12px 16px` mobile. Trigger button: `padding: 12px 0; min-height: 44px`.
- **Header region is ↗-free** (verified: `sed -n '/<header>/,/<\/header>/p' dist/aaro/index.html | grep -c '↗'` = 0). Source-list ↗ markers preserved in footer (9 occurrences in dist/aaro/index.html).

## Decisions & Deviations

### Decisions (also in frontmatter)
- Build-time invariant gate runs in Nav.astro frontmatter so drift in stories.json fails the build at compile time rather than producing a partially-rendered nav. Footer.astro relies on the same invariant (single source of truth: stories.json + Nav.astro gate).
- Constants `ABOUT_PAGES` (Nav) and `SITE_PAGES` (Footer) are intentionally duplicated rather than extracted to a shared module — keeps the two components independent for label-only display tweaks at the small cost of 6 literal entries × 2 files.
- Mobile dropdown reveal uses JS click toggle (matchMedia-gated) rather than relying on `:focus-within`. On touch devices the trigger button does not consistently retain focus after first tap, which would cause flicker mid-tap.
- Stories footer column shows 4 (not 6) featured stories per CONTEXT.md "Footer surface" guidance (4-6 curated) — chosen to keep column height proportional to Source/License.

### Verify-command artifact note (not a deviation, documented for the next agent)

The plan's Task 2 verify line uses `grep -cE 'href="/(about|foia|glossary|map|timeline|whatsnew)/"' dist/aaro/index.html | awk '{ if ($1+0 >= 6) exit 0; else exit 1 }'`. Astro emits the page HTML with `<head>` and `<body>` largely on single lines (minified-ish), so `grep -c` counts **lines containing a match**, not match occurrences. The semantically correct count is `grep -oE | wc -l` which yields 12 (6 slugs × 2 = nav + footer). Both per-slug grep counts confirm each unique href appears (2×). Future Plan 04.1-07 verification should use `grep -oE | wc -l` or per-slug grep rather than `grep -cE`.
