## Decisions Made

- **Defense-in-depth `<slug>/index.html` skip in Task 2:** Coded `git ls-files`-driven enumeration with explicit skip-if-equals-`<slug>/index.html` for the 5 partial-port slugs, even though zero of them currently track a legacy `<slug>/index.html` (Astro `src/pages/<slug>/index.astro` is the route owner). This makes the script idempotent and matches the W-6 contract in `04.1-PLAN-CHECK.md`: Plan 04.1-02 will rewrite `copy-legacy-archives.sh`'s skip rule from `case "$f" in <slug>/index.html) continue ;;` to `case "$f" in legacy/<slug>/index.html) continue ;;` — same defensive shape.

- **Anchor audit dispatched 20 chrome-scrape files to "Legacy 301" instead of forcing SSG re-wrap:** 10 `aaro/pages/*.html` are verbatim DoD/DMA template scrapes (with full Defense Media Activity skin-header, banner, footer chrome — 30-50 inline scripts each); 9 `nara/pages/*.html` are verbatim archives.gov scrapes (with `<div class="page-body-wrapper">` + full archives.gov nav/footer); `embed.html` is a single-purpose widget shell. Re-wrapping any of these in `RootLayout` would either double-render chrome or break the widget. Disposition: 301 redirect to the official source in Plan 04.1-06. The audit documents this clearly for Plans 04.1-03/04 so the extractor does NOT enumerate them.

- **Selector cascade explicitly forbids raw `<body>` fallback:** Cascade-4 is "FAIL with clear error pointing back to the audit" — NOT "extract `<body>` and hope for the best". Pre-Phase-4 build-script HTML embeds its own Nav/Footer/scanlines chrome inside `<body>`, so a `<body>`-based extractor would double-render every page. The audit documents this trade-off explicitly so future plan iterations can't silently weaken it.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Worked around Bash `grep -cv … || echo 0` defect in Task 2's plan-supplied verify expression**

- **Found during:** Task 2 verification
- **Issue:** The plan's automated verify command for Task 2 was `[ "$(git ls-files aaro/ | grep -cv '^aaro/index.html$' || echo 0)" = "0" ] && [ ... nara, nasa ... ]`. When `git ls-files <slug>/` returns empty (which is the desired post-move state for all 5 partial-port slugs in this plan), `grep -cv` exits with status 1 (no matches), causing the `|| echo 0` to fire and concatenate a second `"0"` to the captured value. The resulting string `"0\n0"` is not literally equal to `"0"`, so the `[ ... = "0" ]` check fails — even though the substantive condition (zero non-index files) is true.
- **Fix:** Re-ran verification with a corrected expression: explicitly count via `wc -l` per slug and assert each is `"0"`. All 5 partial-port slugs (aaro, nara, nasa, nz, uruguay) confirmed at zero non-index tracked files. Final acceptance criteria met. The plan's verify-expression defect is a documentation/automation issue, NOT a substantive task failure.
- **Files modified:** None (verification-only workaround; the plan-level Verification block at the end of PLAN.md uses a different idiom that does pass correctly).
- **Verification:** Independent `wc -l` check + plan-level Verification block (a), (b), (c), (d), (e), (f) all PASS. See verification log in commit message of Task 2 (`bdcd685`).
- **Committed in:** Task 2 commit `bdcd685` proceeded after substantive verification pass; no plan rewrite — the original verify text is preserved in PLAN.md as-is so the planner-authored intent stays auditable.
