## Goal

Re-activate the six informational site pages (`/about/`, `/foia/`, `/glossary/`, `/map/`, `/timeline/`, `/whatsnew/`) as Astro routes that extract body content from `legacy/<slug>.html` at build time via the shared `extractLegacyBody.ts` cascade (created in Plan 04.1-03 Task 2 — `<main>` → `<article>` → audited fallbacks → throw; no raw `<body>` fallback per B-3 fix), scrub legacy chrome (B-4 fix), and wrap in `RootLayout` with `archiveSlug="wargov"` (cross-cutting pages use the default wargov gold tone) and `pageType="site-page"` (B-1 fix — Pagefind indexes these unconditionally). For `/map/` and `/timeline/`, `scrubChrome` is called with `preserveScripts: true` so audited body-region interactive scripts are preserved INSIDE the extracted anchor slice — NOT from legacy `<head>` (W-4 fix). The four parked utilities (`/donate.html`, `/embed.html`, `/compare.html`, `/stats.html`) are NOT migrated — they stay in `legacy/` and are handled by redirect-to-gone in Plan 04.1-06. Nav + Footer surface integration is in Plan 04.1-05.

This plan depends on `04.1-03` (not just `04.1-01`) because `extractLegacyBody.ts` is OWNED and WRITTEN by Plan 04.1-03. This plan only IMPORTS the module — `src/scripts/extractLegacyBody.ts` is intentionally NOT in this plan's `files_modified`. The dependency promotes this plan to wave 3 (after 04.1-03 finishes in wave 2).

## Threat model

| Boundary | Description |
|----------|-------------|
| legacy HTML → `set:html` | Verbatim TEXT injected after chrome scrub; same trust model as 04.1-03 |
| preserveScripts=true → preserved JS in dist | Interactive map/timeline behaviour depends on this; tampering of legacy file would persist. Scripts MUST come from the anchor slice ONLY (W-4) |
| RootLayout pageType="site-page" | Forces Pagefind body marker; site-pages indexable regardless of archive context |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.1-04-01 | XSS | `set:html={bodyHtml}` in 6 routes | mitigate | Source is git-tracked public-domain government text passed through `scrubChrome`. Code comment documents trust boundary. Verify gate asserts zero `<style>`/`<link>`/`<header>`/`<footer>`/inline `style=""` inside every page-body article. |
| T-04.1-04-02 | XSS | preserved `<script>` blocks in /map/ /timeline/ | mitigate | preserveScripts only enabled for the 2 entries that need it (Task 1 verify asserts the set is exactly {map, timeline}). Scripts come ONLY from the extracted anchor slice; legacy `<head>` scripts are never reached because `extractMain` returns only the anchor content (W-4 fix). |
| T-04.1-04-03 | Denial of Service | legacy file missing at build time | mitigate | Task 1 verify asserts `fs.existsSync(legacyPath)` for all 6. `extractMain` throws with actionable file-path error if anchor missing (B-3 fix). |
| T-04.1-04-04 | Tampering | trailing-slash drift between Astro output and URL contract | accept | Cloudflare Pages auto-handles trailing slashes; _redirects in 04.1-06 lock the canonical form. |
| T-04.1-04-05 | Denial of Service | site-pages invisible to Pagefind | mitigate | Task 2 sets `pageType="site-page"` on RootLayout (B-1 fix). Verify-task asserts no `data-pagefind-ignore` on any built site-page HTML. Plan 04.1-07 re-asserts via Pagefind grep for `FOIA` + `glossary` + `timeline`. |
| T-04.1-04-SC | Tampering | npm/pnpm installs | accept | No new packages — uses only existing astro / node:fs and the shared `extractLegacyBody.ts` module owned by Plan 04.1-03. |
