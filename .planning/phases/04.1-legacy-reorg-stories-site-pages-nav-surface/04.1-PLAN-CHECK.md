## 1. Verdict & rationale

The 7 plans are well-structured, dependency-ordered, and largely faithful to CONTEXT.md/UI-SPEC.md. However, two BLOCKERS will silently break the central deliverable ("user can search for stories"), and two more BLOCKERS will break the CI drift gates that Phase 4-20 wired. Plans require revision before execution.

The good: requirement coverage is complete, threat models present on every plan, atomic-commit discipline implied by per-task `<files>` scoping, no scope creep into Phase 5/6 territory, deferred items (compare/donate/embed/stats migration, dormant re-activation, story authoring) stay out of scope.

The bad (executive summary):
1. **BLOCKER — Pagefind indexes 0 dormant-archive stories.** RootLayout gates `data-pagefind-body` on `ACTIVE_ARCHIVES = {wargov, aaro, nasa, nara}` and ALSO emits `data-pagefind-ignore` on `<main>` for any other slug. Plan 04.1-03 puts `data-pagefind-body` on the inner `<article>`, but Pagefind's `data-pagefind-ignore` on the parent `<main>` overrides ANY inner body marker. Consequence: `/stories/rendlesham/` (uk), `/stories/trans-en-provence/` (geipan), `/stories/varginha/` (brazil), `/stories/falcon-lake/` (canada) — half the featured-list — will be invisible to search. Plan 04.1-07 Task 1 verify EXPLICITLY greps for `rendlesham` hits in `dist/pagefind/` and will fail.
2. **BLOCKER — URL-CONTRACT.txt drift gate broken by silent path mismatch.** `scripts/snapshot-urls.py` walks every tracked HTML and maps `legacy/aaro/tic-tac.html` → public URL `/legacy/aaro/tic-tac.html`. Plan 04.1-01 moves files into `legacy/` but Plan 04.1-06 hand-edits URL-CONTRACT.txt without updating `snapshot-urls.py` to exclude `legacy/`. Any future `snapshot-urls.py` invocation re-injects polluted `/legacy/*` routes and clobbers hand-edits.
3. **BLOCKER — Story body `set:html` will be empty for most legacy files.** `extractMain` regex `/<main\b[^>]*>...<\/main>/i` assumes legacy files have a `<main>` tag. Real inventory check: legacy AARO/NARA/NASA story files were generated by `build-*.py` pre-Phase-4 — most use `<article>` or `<section class="story-body">`, not `<main>`. The fallback to `<body>` returns the ENTIRE body including the legacy nav, footer, lightbox, AND the same nav/footer Astro is about to render again. Result: every story page double-renders the nav/footer/scanlines. Plan 04.1-03 does not enforce a pre-flight check that `<main>` exists in every legacyPath.
4. **BLOCKER — Scope-reduction smuggled into Task 2.3 of Plan 04.1-03.** Plan ships `extractMain` returning RAW HTML via `set:html` including any leaked `<style>`, `<script>`, and `<link>` tags from legacy files. The threat-model accepts this as "v1" but per CLAUDE.md §9 and CONTEXT.md decisions, the contract is "verbatim official text wrapped in RootLayout". Leaked legacy `<style>` blocks override site-wide tone-colour CSS variables (legacy files had inline color CSS); leaked legacy `<link rel="stylesheet">` hits broken paths (legacy CSS lived at `/assets/style.css` which exists, but the legacy `<style>` blocks ALSO define tokens that conflict with RootLayout). This is silent scope reduction — CONTEXT.md does not authorise "v1 with style leakage; scrubbing in future plan". Either scrub now or split the phase.

See §3 for full blocker analysis, §4 for warnings, §5 for goal-coverage matrix.

## 3. BLOCKERS (must fix before execution)

### B-1 — Pagefind silently excludes 4 of 8 featured stories (and ~10+ non-featured)

**Dimension:** key_links_planned + verification_derivation
**Plan:** 04.1-03 + 04.1-07
**Severity:** BLOCKER

**Evidence:**
- `src/layouts/RootLayout.astro` line 88-89: `ACTIVE_ARCHIVES = new Set(['wargov', 'aaro', 'nasa', 'nara'])`.
- RootLayout line 91: `const isDormant = !ACTIVE_ARCHIVES.has(archiveSlug)`.
- RootLayout line 119-121:
  ```astro
  <main
    data-pagefind-body={isActiveForSearch ? '' : undefined}
    data-pagefind-ignore={isDormant ? '' : undefined}
  >
  ```
- Plan 04.1-03 stories.json maps featured stories to archives including `uk` (rendlesham), `geipan` (trans-en-provence), `brazil` (varginha), `canada` (falcon-lake) — all dormant.
- Per Pagefind docs (pagefind.app/docs/indexing): `data-pagefind-ignore` on a PARENT element causes Pagefind to skip the entire subtree, including any inner `data-pagefind-body` markers.

**Consequence:**
- Plan 04.1-03 truth #5 ("Pagefind index contains hits for `tic-tac`, `roswell`, `rendlesham`") — FAILS at run for `rendlesham`.
- Plan 04.1-07 Task 1 automated verify (`for term in tic-tac roswell rendlesham FOIA glossary;...`) — FAILS.
- UI-SPEC §3.1 contract ("data-pagefind-body on <article.story-body> so search indexes story prose") — broken by RootLayout's outer override.

**Fix paths (pick one):**
1. Extend ACTIVE_ARCHIVES set in RootLayout to include stories slug-aware logic. Cleanest: add `archiveSlug` prop OR a new `forceIndexing: true` prop to RootLayout; story+site-page routes set it; RootLayout emits `data-pagefind-body` and OMITS `data-pagefind-ignore` when `forceIndexing` is true.
2. Refactor RootLayout to compute Pagefind markers from a NEW prop `routeType: 'archive' | 'story' | 'site-page'` (or `pagefindMode: 'active' | 'ignore' | 'forced'`), with stories+site-pages defaulting to `forced`/`active`.
3. (Hack — NOT recommended) Add a 9th plan that patches RootLayout post-04.1-05.

**Required addition to plan tree:** new Wave 1 sub-task in 04.1-03 OR new Wave 2 plan inserted before 04.1-05, modifying RootLayout's Pagefind marker logic.

## R2.5 New issues introduced by the revision

### N-1 (Nit, non-blocking) — Python heredoc shell-escape complexity in 04.1-04 Task 2 verify

Plan 04.1-04 Task 2 verify embeds a python regex inside a bash `bash -c '...'` heredoc with nested escapes:

```python
bad=re.search(r'<style\\b|<link\\s+rel=[\\\"\\']?stylesheet|...', body)
```

The triple-escaped `[\\\"\\']` is fragile — it may parse correctly under one bash version but fail under another (escaping rules differ between bash 3.2 macOS and bash 5.x Linux). This is an execution-time concern, not a plan-design blocker — the assertion logic is correct; only the escape rendering is risky. Recommendation: at execution time, if the inline python fails, factor it out to a small file `scripts/verify-no-chrome-leakage.py` and invoke that from verify. Mark as nit; do not block.

### N-2 (Nit, non-blocking) — 04.1-03 Task 0 verify on `dist/geipan/index.html` is conceptually orthogonal

Plan 04.1-03 Task 0 verify says:
```bash
grep -q 'data-pagefind-ignore' dist/geipan/index.html && ! grep -q 'data-pagefind-body' dist/geipan/index.html
```

But `dist/geipan/index.html` is produced by `copy-legacy-archives.sh` from `legacy/geipan/index.html` — it doesn't pass through RootLayout. The legacy HTML may or may not have those markers (likely does NOT, since pre-Phase-4). The assertion as written is non-functional: it checks something orthogonal to the test goal. The acceptance criteria text immediately following the verify acknowledges this ("irrelevant since it's a legacy copy") and pivots to `dist/nz/index.html` (which IS Astro-rendered with default pageType='archive' + dormant slug). Recommendation: the verify block should drop the geipan assertion or replace with the nz assertion that the acceptance criteria already uses. Non-blocking — the acceptance criteria explicitly supersedes the verify block's geipan check, and the real B-1 regression is caught by Plan 04.1-07 Task 1 Step 2.5 for rendlesham/trans-en-provence/varginha/falcon-lake.
