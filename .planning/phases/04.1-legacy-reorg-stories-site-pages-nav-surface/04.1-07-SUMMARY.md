## Known limitations / accepted deviations

### 1. `astro preview` not available

The `@astrojs/cloudflare` adapter does not support the `astro preview`
command (preview command throws). Used `python3 -m http.server` for
canonical 200 testing as a clean static-file substitute. Wrangler `pages
dev` is the next option but see (2).

### 2. `wrangler pages dev dist/` bypasses `_redirects`

The build emits `dist/_worker.js` (Cloudflare adapter SSR worker) and
`dist/_routes.json`. When wrangler boots, the worker intercepts every
request and serves dynamically, **bypassing the static `_redirects`
parser**. Even after copying `_redirects` into `dist/`, every test path
returned 200 (worker fallback to root). The `_redirects` rules are
statically correct (drift gate confirms) but **end-to-end 301 verification
is deferred to the Cloudflare Pages deploy preview** (Phase 6 task).

### 3. `/search.html` → 404 via static file server

Astro built `dist/search/index.html` (slug routing); `URL-CONTRACT.txt`
lists `/search.html` (legacy literal path). The `_redirects` 200-rewrite
rule `/search.html /search.html 200` would handle this in CF Pages
production. With the python static server, `/search.html` is a 404
(static-file-not-found). This is a **pre-existing Phase 4 inconsistency**,
NOT a Plan 04.1 regression. `verify-redirects.sh` reports 66/67 passes.

### 4. Wargov landing page `/` perf 0.78

Pre-existing Phase 4 regression (hero carousel + slideshow images ship in
`<head>`; LCP 4.4 s, 8.2 MB transfer). NOT introduced by Phase 04.1 —
recorded here for context. Plan 04.1 routes (`/stories/`, `/stories/tic-
tac/`, `/about/`, `/timeline/`) all hit perf ≥ 0.97.

### 5. `verify-lighthouse-budgets.py` doesn't parse `.lighthouserc.json` assertions

The script expects `largest-contentful-paint` / `total-byte-weight` audit
IDs in `assertion-results.json`, but the legacy `.lighthouserc.json`
asserts on `categories:*` minScore (warn-only). The `.lighthouserc.cf.json`
asserts on the budget audits (hard-fail) but is only invoked in the CF
Pages CI workflow, not locally. Result: `verify-lighthouse-budgets.py`
exits 2 ("no budget audits found"). Per-URL Lighthouse scores are still
captured in `.lighthouseci/lhr-*.json` — the LCP + transfer columns in
the table above were extracted via direct JSON parsing. **Not a Plan 04.1
deliverable bug; flagged for Phase 6 follow-up.**

## Deviations from plan

### Auto-fixed Issues

**1. [Rule 3 — env fix] `astro preview` unsupported → swap to `python3 -m http.server`**

- **Found during:** Task 1 Step 3 (curl harness server boot).
- **Issue:** `pnpm exec astro preview` exits with `[preview] The @astrojs/cloudflare adapter does not support the preview command.` This blocks the curl harness step.
- **Fix:** Booted `python3 -m http.server 4321 --directory dist --bind 127.0.0.1` as the canonical 200 testing server. Static-file-only — bypasses both the Astro adapter constraint and the wrangler `_worker.js` interception. Curl harness ran cleanly and 66/67 canonical routes pass.
- **Files modified:** None (workspace-only env fix).
- **Commit:** N/A (env fix, not a code change).

**2. [Rule 3 — env fix] Wrangler `_worker.js` bypasses `_redirects`**

- **Found during:** Task 1 Step 3 (redirect 301 spot-checks).
- **Issue:** Booted `wrangler pages dev dist/` to test the `_redirects` 301 rules. Every test path (including paths with no physical file like `/about.html`) returned 200, because `dist/_worker.js` (Cloudflare adapter SSR runtime) intercepts every request before `_redirects` is consulted.
- **Fix:** Documented as Known Limitation #2. Deferred 301 verification to the Cloudflare Pages deploy preview (Phase 6). The `_redirects` file itself is statically correct (drift gate confirms 122 301 rules; spot-check `grep -F` matches all 8 sample rules).
- **Files modified:** None (test-method documentation, not a code fix).

**3. [Rule 3 — env fix] Subshell PATH stripped under for-loop execution**

- **Found during:** Task 1 curl harness loops.
- **Issue:** Inside `for ... do` loops, the eval'd subshell lost PATH entries to `/usr/bin`, causing `curl`, `head`, `awk`, `tr` to report `command not found`. Even after `export PATH=...` immediately before the loop.
- **Fix:** Used absolute binary paths (`CURL=/usr/bin/curl`, etc.) inside loops. Workspace-only quirk; no source change.
- **Files modified:** None.
